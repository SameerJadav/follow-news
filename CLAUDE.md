# CLAUDE.md

This file is the resumability contract for this repo. It exists because
`product.md` says the project is "built once and then left alone… no one's
coming back to patch it." If you are reading this a year from now with no
memory of the project, this file plus the three spec docs below should be
enough to work safely.

## What this is

A phone-only daily news app, generated by GitHub Actions and published to
GitHub Pages, at `https://sameerjadav.github.io/follow-news/`. Two sections
(World, India) carrying only the genuinely biggest stories, written in plain
adult English from claims individually anchored to sources. An opt-in
**Follow** feature researches a story's full backstory and appends a
timeline entry per day until it closes. Free tiers only, no server, no
database — `data/` and `followed/` on disk are the entire backend.

**`product.md`, `research.md`, `decisions.md` are the specification.** They
are settled; do not edit them, and do not silently contradict them. If a
future change needs to deviate from something they say, stop and say so
rather than guessing.

## Commands

```sh
uv run digest.py                      # full pipeline: gather -> select -> claims -> write -> render
uv run digest.py --if-missing         # no-op if today's data/YYYY-MM-DD.json already exists (cron uses this)
uv run digest.py --feeds PATH         # use an alternate feeds.txt (e.g. to test degradation)
uv run digest.py render               # re-render docs/ from data/+followed/ only; needs no API key
uv run digest.py follow               # process open Follow issues, append timelines, re-render
uv run digest.py follow --issue 12    # restrict to one issue (used by follow.yml)
uv run digest.py follow --date ...    # override the digest date (testing)
uv run digest.py health               # cross-day feed-decay report over committed data/; exits 1 if unhealthy
uv run digest.py review               # calibration evidence for the newest digest
uv run digest.py review --date ...    # calibration evidence for one past day

uv run pytest -q                      # the whole test suite, no network, no key

GEMINI_API_KEY=... DIGEST_DUMP_DIR=/tmp/fixtures uv run digest.py   # dump raw LLM responses for new fixtures
DIGEST_WAIT_BUDGET_S=5 uv run digest.py                              # shorten the 429 wait budget for local testing
```

## Architecture

Pipeline order, one module per concern:

- **`feeds.py`** — load `feeds.txt`, fetch/parse RSS, the article time
  window, dedupe, per-feed health (`FeedHealth`/`GatherResult`), and the
  quorum decision (`quorum_ok`).
- **`rank.py`** — pool shaping (per-outlet cap), the scoring/cutoff
  mechanism (`WEIGHT_FLOOR` and friends), scope filtering, no network I/O —
  fully unit-testable.
- **`wikipedia.py`** — the Current Events Portal cross-check, a curated
  human check against volume bias.
- **`llm.py`** — the three Gemini calls (select, claims, write) that are the
  entire quota strategy.
- **`extract.py`** — article text extraction: JSON-LD, then paragraphs,
  longest wins; escalate to Jina (`r.jina.ai`) only if both fall short.
- **`anchor.py`** — the semantic gate on write-pass output: marker/claim
  validation, thin-sourcing detection, vocab cleaning.
- **`render.py`** — every HTML page, generated from Python template
  strings. Never hand-edit its output.
- **`follow.py` + `ground.py`** — Follow: issue parsing, the owner guard,
  grounded backstory/timeline generation via Gemini + Google Search.
- **`ratelimit.py`** — 429 classification and budgeted wait-and-resume,
  shared by `llm.py` and `ground.py` (Phase 6).
- **`report.py`** — read-only reports over committed `data/*.json`: cross-day
  feed decay, and the calibration evidence for `review` (Phase 6).
- **`digest.py`** — the CLI entrypoint and orchestration; owns the `data/`
  contract (`write_digest`) and the stale-page fallback (`_render_stale`).

**Workflows:** `digest.yml` (three staggered `--if-missing` crons +
`workflow_dispatch`; builds, commits, deploys, then a non-gating `health`
job), `render.yml` (push-triggered re-render, no API key), `follow.yml`
(issue-triggered, owner-gated).

## Invariants — do not break these

- `data/YYYY-MM-DD.json` and `followed/<issue>.json` are the only sources of
  truth. Every page in `docs/` is *derived* and overwritten wholesale on
  every render. Never hand-edit generated HTML.
- `docs/style.css`, `docs/app.js`, `docs/robots.txt`, `docs/.nojekyll`,
  `docs/manifest.webmanifest`, and the icons are hand-written and are never
  written or touched by the pipeline.
- **3–4 LLM calls per morning, total** — never one call per article, per
  story, or per section. Select reads cheap headlines only; full text is
  fetched only for what selection chose; claims and writing are each one
  batched call.
- The write pass sees **claims only, never raw article text** — a fact that
  isn't an anchored claim has no way into the prose. Numbers are never
  averaged or blended across sources; two disagreeing figures become two
  claims, each attributed.
- **Nothing follows itself.** No story is tracked, updated, or resurfaced
  unless a Follow issue was deliberately opened by the owner.
- The digest must keep publishing even if Follow fails entirely — Follow
  runs `continue-on-error: true` and is never on the digest's critical path.
- Follow batches timeline updates across all active follows in one call;
  never one call per followed story.

## Security

- The repo is public. `GEMINI_API_KEY` lives in Actions secrets only —
  never echo it, never write it into `data/`, `docs/`, `followed/`, or a log
  line. `gh secret list` should show exactly `GEMINI_API_KEY`.
- No workflow may use `pull_request_target`.
- `follow.yml` is job-gated on
  `github.event.issue.user.login == 'SameerJadav' && contains(labels, 'follow')`
  — the repo is public, so anyone can open an issue, and this guard is what
  stops a stranger from driving the pipeline and burning quota.
  `follow.fetch_issues()` re-checks the author independently in Python, so
  the guarantee holds even if this workflow is ever invoked another way.
- **Never interpolate `github.event.issue.title` or `.body` into a `run:`
  block** — that's attacker-controlled text on a public issue tracker, and
  doing so is a script-injection risk. `follow.py` reads the issue body
  itself via the GitHub API instead. The issue *number* is safe to pass
  through `env:` (it's a GitHub-assigned integer).

## Reliability model (Phase 6)

- **429s wait, they don't fail.** `ratelimit.call_with_resume` (used by both
  `llm.py` and `ground.py`) distinguishes a rate limit from a real failure,
  honours the server's own `retryDelay` when present, and waits inside a
  time budget (`ratelimit.WAIT_BUDGET_S`, default 45 min) rather than a
  fixed attempt count. A *daily*-scoped quota (quotaId containing "PerDay")
  re-raises immediately instead of sleeping for hours — the three staggered
  `--if-missing` crons are what "resume" means for a day-scale limit.
  Measured live 2026-07-25: `gemini-3.6-flash` free tier is
  `GenerateRequestsPerMinutePerProjectPerModel-FreeTier = 5 RPM`; real usage
  is 2-3 pipeline calls plus 0-2 grounded Follow calls per morning, so this
  is not the tight constraint it might look like on paper.
- **Degrade, don't fail.** `feeds.quorum_ok` (`MIN_LIVE_FEEDS=3`,
  `MIN_ARTICLES=20`) is the floor below which there isn't enough real news to
  call it a digest; above that floor, a run with half its feeds dead
  (`DEGRADED_LIVE_SHARE=0.5`) still ships, loudly logged as degraded.
- **A failed morning still publishes something honest.** Any early return in
  `run_pipeline` (quorum failed, or any LLM pass returned nothing usable)
  returns `False`. `main()` then calls `digest._render_stale`, which
  re-renders `docs/` with today's IST date while `data/`'s newest file is
  still yesterday's — exactly the condition `render._stale_html` renders the
  "isn't ready yet" banner unhidden for — and exits 1. `digest.yml`'s commit,
  upload, and deploy steps all carry `if: always()` so that stale, honestly
  labelled page still reaches Pages, and the run itself shows red so GitHub
  emails the owner.
- **The `health` job never gates the digest.** It's a separate job in
  `digest.yml` (`needs: build`, `if: always()`) that runs
  `digest.py health` against committed `data/` only — no API key. It fails
  (and emails the owner) when a feed has been silent `report.DEAD_DAYS` (3)
  consecutive days, or today's run itself came back degraded. A single quiet
  day for an otherwise-healthy feed does not fail it.

## Calibration dials (Phase 6 Part B tunes these, not prompt wording, first)

| Dial | Where | What it does |
| --- | --- | --- |
| `WEIGHT_FLOOR` | `rank.py` | the cutoff a cluster's weight must clear to make the digest |
| `TIER_WEIGHT`, `WIKI_BONUS` | `rank.py` | how tier and the Wikipedia cross-check add to weight |
| `HARD_CAP`, `MIN_STORIES_IF_ANY` | `rank.py` | ceiling on stories kept; floor when the cutoff would empty the digest |
| `MAX_ARTICLES_PER_STORY` | `rank.py` | how many articles per story feed the claims pass |
| `WORD_TARGET` | `anchor.py` | target length per tier |
| `THIN_MIN_CLAIM_OUTLETS`, `THIN_MAX_OUTLET_SHARE` | `anchor.py` | thin-sourcing thresholds |
| `MAX_UNANCHORED_SHARE`, `MIN_MARKERS`, `MIN_BODY_WORDS` | `anchor.py` | anchoring-quality floors a story must clear to survive |
| `WINDOW_FLOOR_H`, `WINDOW_CAP_H` | `feeds.py` | the article time window's floor/cap |
| `MIN_LIVE_FEEDS`, `MIN_ARTICLES`, `DEGRADED_LIVE_SHARE` | `feeds.py` | the quorum/degradation thresholds |
| `DEAD_DAYS`, `HISTORY_DAYS` | `report.py` | how many silent days call a feed dead, and the lookback window |
| `STALE_DAYS` | `follow.py` | days with no development before a Follow auto-closes |

Turn one of these, backed by an observation logged in `calibration.md`,
before rewording an `llm.py` prompt — a prompt change moves editorial
judgement (story count, section split, scope, register) and should be shown
to the owner before it ships, per `decisions.md`.

## Gotchas

- `BASE_URL` (`digest.py`) is `https://sameerjadav.github.io/follow-news/`.
  The local checkout directory is named `daily-digest-new` — that name must
  never leak into a URL or a committed path.
- After editing a template string in `render.py`, you must re-render
  (`uv run digest.py render`) to see the change — editing generated HTML in
  `docs/` directly is pointless, it gets overwritten.
- `html.escape(value, quote=True)` every interpolated value used inside an
  HTML attribute.
- **Feeds that must never be re-added** (tested 2026-07-25, `research.md`
  §2.3): AP, Reuters, UN News, Deccan Herald national, Business Standard,
  PIB → 401/403/404. The Wire, The Print → HTTP 200 with zero items — this
  is exactly the trap `feeds.py`'s health check exists to catch generically,
  not just for these two.
- **Times of India is the extraction acceptance test.** JSON-LD works for
  Indian outlets and is absent on BBC/Al Jazeera/Guardian/The Hindu;
  paragraph extraction works for those and fails on TOI (author-bio
  boilerplate). If TOI yields under ~1,000 chars, extraction is broken.
- NDTV 403s a normal User-Agent; `extract.py` escalates to the free, keyless
  `r.jina.ai` reader proxy (20 RPM) only when the normal fetch falls short.
- **Gemini grounding cannot use `response_schema`.** Sending
  `response_mime_type="application/json"` alongside the `google_search` tool
  is a `400 INVALID_ARGUMENT`. `ground.py`'s batched timeline call instead
  asks for a delimited text format and parses it in Python.
- Grounding's `grounding_supports` segment offsets are **byte** offsets, not
  character offsets — `ground._char_offsets`/`_byte_to_char` convert; a
  non-ASCII outlet name or currency symbol is exactly where a naive
  character-offset slice would go silently wrong.
- Grounding's `vertexaisearch.cloud.google.com` redirect URLs expire in
  roughly 30 days; `ground._resolve` follows them to the real publisher URL
  once, at generation time, and that resolved URL is what gets stored —
  never the redirect.
- `GROUND_MODEL` (`gemini-2.5-flash`) is pinned to the model verified to
  actually ground successfully on the free tier — Gemini 2.5 Pro returned a
  hard `limit: 0` for both requests and input tokens when tested
  2026-07-25, despite being what `product.md`/`decisions.md` name.
- **`X-Robots-Tag` is not achievable on GitHub Pages** — it serves fixed
  headers with no configuration surface (`curl -I` confirms no such header
  is ever present). `docs/robots.txt` (`Disallow: /`) plus
  `<meta name="robots" content="noindex, nofollow">` on every page
  (`render._HEAD`) are the complete achievable mechanism, and they satisfy
  what `product.md` actually promises.
- Free-tier RPD/RPM is unpublished and moves without notice — `research.md`
  §3.1 recorded 50-80% cuts in December 2025. Re-run the quota probe
  described in the Phase 6 write-up if 429s start looking different from
  what's documented above.

## Debugging a scheduled run

Everything interesting is only visible after the fact — `dbg()` in every
module writes to stderr, never into the site, specifically so a 02:00 IST
run can be diagnosed afterwards.

```sh
gh run list --limit 10                 # recent runs and their status
gh run view <id> --log                 # full log, every dbg() line
gh run view <id> --log-failed          # just the failing step
gh run watch                           # follow an in-flight run
```

Greppable `dbg()` prefixes worth knowing: `llm: call #`, `ratelimit:`,
`gather:`, `QUORUM`, `DEGRADED`, `ZERO ITEMS`, `rank:`, `wiki: NOT COVERED`,
`follow:`, `ground:`, `anchor: DROPPED`/`THIN-SOURCED`.
