## What the pipeline does

A GitHub Action runs `digest.py` at ~02:00 IST. Stages, in order:

1. **gather** (`feeds.py`) — fetch every RSS feed in `feeds.txt`, keep
   articles inside the time window, dedupe by canonical URL and by
   normalised title. `quorum_ok` decides whether there is enough news.
2. **pool** (`rank.py`) — cap each outlet's share so a high-volume feed
   can't crowd out the rest. This is what the select prompt sees.
3. **wikipedia** (`wikipedia.py`) — the Current Events Portal, a curated
   human check against volume bias.
4. **select** (`llm.py`, LLM call 1) — headlines and summaries only, no
   article text. Returns clusters of article ids.
5. **rank** (`rank.py`) — score each cluster (distinct outlets + tier
   weight + wiki bonus) and cut below `WEIGHT_FLOOR`. No network.
6. **extract** (`extract.py`) — fetch full text for surviving clusters
   only: JSON-LD and paragraph extraction from one fetch, longest wins,
   escalating to the r.jina.ai reader proxy if both fall short.
7. **claims** (`llm.py`, one LLM call PER SECTION) — atomic claims, each
   anchored to exactly one article URL. Per section since 2026-08-23: one
   batched call decayed with prompt position and India was always last.
8. **write** (`llm.py`, the last LLM call) — prose from claims ONLY; the write
   pass never sees article text. `anchor.py` then validates each story
   and drops any that isn't genuinely claim-anchored.
9. **render** (`render.py`) — regenerate `docs/` wholesale.

Four LLM calls per morning, total. Any stage returning nothing ends the
run: `docs/` is re-rendered with an honest "not ready yet" banner and
the process exits 1.

## Artifact index

Per captured day, under `debug/<date>/`:

| path | what it holds |
|------|---------------|
| `run.json` | outcome, stage timings, dial values, git sha, env |
| `funnel.json` | the counts in the table above |
| `trace.jsonl` | ordered timeline: every log line and structured event |
| `feeds/index.json` | per-feed health, plus every article dropped and why |
| `feeds/*.xml` | raw RSS bytes as served |
| `pool.json` | the exact article pool the select prompt saw, with its indices |
| `wikipedia/` | raw wikitext, parsed events, coverage misses |
| `rank.json` | every cluster considered, its weight arithmetic and verdict |
| `extract/index.json` | per-article scrape: status, per-strategy yields, winner |
| `extract/*.html` | the raw page fetched |
| `extract/*.txt` | the text actually handed to the claims pass |
| `extract/*.jina.txt` | the reader-proxy body, when it was used |
| `llm/*.prompt.txt` | the full prompt sent |
| `llm/*.response.json` | the raw model response |
| `llm/*.meta.json` | model, latency, tokens, finish reason, retries |
| `claims.json` | claims per cluster, with the source kind behind each |
| `anchor/index.json` | every story judged, its metrics against each threshold |
| `anchor/dropped-*.json` | full context for a story that was thrown away |
| `render.json` | pages written and their byte sizes |
| `follow/` | grounded prompts, responses, resolved redirect URLs |
| `dossier/<issue>/index.json` | a followed story's research: rounds, calls, ledger size, entity sides, gap firings |
| `dossier/<issue>/discarded-questions.json` | every question the drift guards cut, and which guard cut it |

A `follow` run against the same day folds `-follow` into every file name
it writes (`run-follow.json`, `extract/index-follow.json`, ...), so the two
runs can never overwrite each other. Both append to `trace.jsonl`.

Published output for the same days is in `data/<date>.json`; the site is
`docs/`, regenerated wholesale on every render.

Only the newest 7 captured day(s) are kept in the working tree (`digest.py prune-debug`, run by the commit step); anything older is in git history only.
